Paper / open a PDF link

Open a PDF link online and start reading.

Skip the file-management detour. Give Paper a public PDF URL and get a reading surface built for the words, not the frame.

A PDF link is already a useful handoff. Paper keeps that simplicity: one public URL in, one comfortable reading view out.

What happens after you paste the link?

Paper checks the source

The URL must use HTTP or HTTPS and resolve to a public network host. Redirect targets are checked too.

Paper reads the text layer

The current MVP works with selectable-text PDFs. It does not pretend a scan is text when there is nothing to extract.

Paper rebuilds the surface

Text, headings, and paragraphs are arranged for a responsive reading column rather than a fixed page viewport.

You keep the source link

Paper is a reading layer. Use the original PDF when you need exact pages, visual layout, or a printable artifact.

Links that work best

Use a direct, publicly accessible PDF URL. Text-first books, reports, papers, essays, and course readings are the strongest fit. The current limit is 30 MB; scanned image-only PDFs, private files, and other formats are outside the supported boundary.

Currently supported formats

Today Paper supports public HTTP(S) links to selectable-text PDFs. That is the whole current format story. Open the supported formats page for the limits and the formats Paper may explore next.

Questions

Can I paste a link that ends in something other than .pdf?

Possibly, if the URL responds with a PDF. Paper checks the returned content rather than relying only on the filename.

Can I share a Paper reading URL?

The current flow starts from the source PDF URL. Paper does not yet create a hosted library or a separate public reading page for each document.
